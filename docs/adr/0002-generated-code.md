# 0002 — Commit generated protobuf code under `gen/go`
Status: accepted · Date: 2026-09-11

## Context
`buf generate` produces Go for three proto packages using three pinned remote
plugins (`protocolbuffers/go`, `grpc/go`, `grpc-ecosystem/gateway`). The
output can either be committed to the repository or regenerated by every
consumer (CI jobs, Dockerfiles, developers) before building.

## Decision
Commit `gen/go/**`. Keep it honest with three mechanisms:

- `buf.gen.yaml` pins exact plugin versions, so regeneration is reproducible.
- The CI `buf` job runs `buf generate && git diff --exit-code -- gen/` and
  fails when a `.proto` was edited without `make proto`, or a plugin was bumped
  without committing the new output.
- `.gitattributes` marks `gen/go/**` as `linguist-generated`, so GitHub
  collapses it in review; `.golangci.yml` excludes it from linting (`go vet`
  still runs over it).

## Consequences
- `go build ./...` and `go test ./...` work on a clean machine and inside the
  multi-stage Dockerfile with nothing but the Go toolchain — no buf, no network
  to buf.build. The README's "`make up` works on a clean machine" promise costs
  nothing extra.
- `github.com/smhunt/sumpnet/gen/go/...` packages are `go get`-able by external
  clients (load-test tools, a future firmware parity checker, the MCP server if
  it is ever split out). A package that only exists after a build step is not.
- Reviewers see the real API surface change (new fields, renumbering) in the
  same PR as the `.proto` diff. `buf breaking` still guards compatibility.
- Proto changes produce larger diffs; plugin upgrades become explicit commits.
  Anyone who edits a proto must run `make proto` — CI tells them within a minute.

## Alternatives considered
- **Ignore `gen/` and generate in CI/Docker.** Smaller tree, but puts buf (and
  reachability of buf.build) on the critical path of every build and makes the
  generated packages impossible to import from outside the repo. Appropriate for
  large monorepos with hundreds of protos; this project has three files.
